# PLAN: Japan street scene (manager-owned)

Goal: a browser 3D scene that looks as close as possible to `japan.webp` (600x550 px, aspect 1.0909): a Kyoto Higashiyama stepped street (Sannenzaka style) at sunset, a weeping cherry (shidarezakura) in full bloom at center, machiya townhouses with kawara tile roofs on both sides, a forested hill and hazy mountains behind, sun glare behind the ridge.

Owner of this file: the manager session (`local_cb2a3cd4-7f93-4e4e-aad4-bd42c66b8ca7`, title "3D Japan scene in browser"). The implementer session does not edit it. Checkboxes are ticked by the manager after verification.

## Decisions (made by the user on 2026-09-05, not to be re-opened)

- Stack: Three.js loaded as ES modules through an import map from a CDN (jsdelivr or unpkg), exact version pinned, `three/addons/` mapped too. No bundler, no build step. Plain `index.html` plus `src/*.js`.
- Assets: fully procedural. Geometry from code, textures drawn on canvas or computed in shaders, sky and clouds from shaders. No downloads at runtime except the Three.js modules. Nothing binary enters Git (see the canon blob ceilings).
- Camera and motion: the page loads framed exactly like the photo. Drag to orbit, wheel to zoom, key `R` and an on-screen button reset to the photo view. Subtle life arrives in phase 5: drifting petals, swaying strands, slow cloud drift.
- Process: manager and implementer are two sessions that message each other, one phase at a time. The manager verifies each phase visually before the next starts.

## Gates (must exist from phase 1, run by `npm test`)

- `npm run dev`: static server for the repo root on http://localhost:8080 (a zero-dependency Node script is fine).
- `npm run shot`: Playwright (chromium) loads the page at 1200x1100, waits for the page's `window.__sceneReady` promise, captures `out/render.png` at the photo view, and fails on any console error.
- `npm run compare`: decodes `japan.webp` and `out/render.png`, prints two scores: mean color distance over a 24x22 grid of cells (lower is better) and grayscale SSIM at 64 px (higher is better). Writes `out/compare.png` as photo | render | 50% overlay | heat-map of the per-cell distance, each panel 600x550.
- `npm test`: runs `shot` then `compare`, then asserts the scores are not worse than the thresholds in `docs/PLAN-scores.md`. That file is implementer-owned. At the end of each phase the implementer raises the thresholds to the achieved values minus a small margin and records the phase's numbers there.
- `npm run perf`: prints median frame time and draw calls over 5 s at 1920x1080 in headless chromium. Budget: under 16 ms median on the dev machine, under 400 draw calls.

User-reported defect, closed in this phase. The user said the scene flickered as they moved the camera. I measured it: identical poses render byte-identically while a 2 mm camera nudge changed 4.76 percent of pixels. My depth-fighting hypothesis was disproved with evidence (24-bit depth measured, near and far swept, post chain disabled, difference image classified). The real cause is geometric aliasing from geometry thinner than a pixel: strand tubes about 0.35 px wide, tile ridges, lattice slats and blossom card edges. Fixed with eight requested multisamples and a 1.2x supersample resolved down, costing 0.6 ms. Drastic changes halved, which I reproduced independently: photo view 0.32 to 0.15 percent, close to the paving 0.57 to 0.28, orbited to zero. Gated by tools/nudge.js in npm test at two device pixel ratios, proved red by reverting the fix, and recorded in docs/learning/defect-register.md.

Carried limitations, reported by the implementer and accepted rather than fixed. The no-warnings box is ticked for the software renderer the gates use; on the GPU path three logs one shader precision warning of its own, and nothing gates warnings. The corridor clamp deliberately allows the camera 0.35 m past the wall faces so the low views stay usable. The petals fall in a box around the canopy rather than on a true wind field, and the animation gate covers 8.7 seconds while the petals wrap on a longer period. The motion bound measures the whole frame, so violent motion confined to a small region could pass it. The scene is least stable close to the paving at device pixel ratio 2, which the nudge gate bounds rather than eliminates.

Not done, and left deliberately. GitHub Pages is not deployed: the workflow is correct but the site has to be switched on once in the repository settings under Pages with source GitHub Actions, and neither session did that, because publishing serves japan.webp, a third-party photograph, publicly. That is the user's decision.
